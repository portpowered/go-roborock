---
title: Camera signaling
description: Own preview signaling while your WebRTC stack owns media.
---

Camera-capable V1 devices require a pattern password and an SDP offer from your WebRTC stack.

```go
camera, err := session.OpenCamera(cameraCtx, roborock.OpenCameraRequest{
    PatternPassword: pattern, SdpOffer: offer,
})
if err != nil { return err }
defer camera.Close()
description := camera.Description()
// Apply description.SdpAnswer and description.TurnServer to your WebRTC stack.
```

`OpenCamera` checks the password and camera readiness before starting preview, then retrieves TURN credentials, sends the offer and any supplied `IceCandidates`, and polls for the device answer. Supply already gathered candidates with the offer so the device can receive them before answer readiness. The offer and answer are plain SDP strings at the public boundary; encoding belongs to the SDK. Quality defaults to HD and may be supplied explicitly. Keep the pattern and TURN credentials private.

When your peer needs TURN settings before creating its offer, use the staged lifecycle:

```go
camera, err := session.PrepareCamera(cameraCtx, roborock.PrepareCameraRequest{PatternPassword: pattern})
if err != nil { return err }
defer camera.Close()
// Configure your peer with camera.Description().TurnServer, then create offer.
description, err := camera.Negotiate(ctx, roborock.CameraOfferRequest{SdpOffer: offer})
if err != nil { return err }
// Apply description.SdpAnswer to that same peer.
```

Preparation owns a real preview and must be closed even if offer creation fails. `Negotiate` accepts one offer per prepared preview; a failure after submission closes that preview rather than retrying an uncertain offer. The caller's request bounds negotiation, while the original camera context bounds the full preview lifetime. `OpenCamera` remains available for callers that already have a complete offer.

Send a plain local candidate with `camera.SendICE(ctx, SendICERequest{Candidate: candidate})`; set `SdpMid` and `SdpMLineIndex` when the candidate belongs to a different media section than the default zero section. Read a device candidate batch with `camera.GetICE(ctx, EmptyRequest{})` and apply every entry in `Candidates`, preserving its media section. `Retry` means the device has not supplied its batch yet. The legacy `Candidate` field contains the batch's first candidate. The caller owns WebRTC negotiation, rendering, and media decoding.

Each preview generates its own owner identity and reuses it only for that preview's start and stop, keeping cleanup separate from other device sessions using the same account. Quality is sent as `HD` or `SD`; the older lowercase inputs remain accepted. The SDK encodes ICE as the provider's JSON candidate envelope rather than a raw candidate string.

If another viewer owns the camera, setup returns `Busy` without starting or stopping its preview or exposing its owner identity. Close the other viewer before trying again. Empty camera reads use the reference protocol's empty positional list. SDP polling waits one second before each of five reads, including the final readiness window.

Only one camera preview may be open per device session; overlapping opens return `Backpressure`. Close it before opening another. Observe `camera.Done()` for lifetime cancellation and termination. Keep the camera context alive for preview. Cancellation and `Close` stop preview with bounded cleanup; setup failure after preview starts also attempts cleanup. Closing the parent device closes owned camera sessions. Close the caller-owned peer connection separately. SDP readiness polling and individual calls have bounded waits; a timeout does not justify retrying movement.

Remote movement uses the device's [remote controls](/docs/guides/remote-control); this release does not expose a separate camera PTZ or playback interface. See [lifecycle](/docs/guides/lifecycle) and the [generated reference](/docs/asyncapi/camera/CameraStartPreviewRPC).
