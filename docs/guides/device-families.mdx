title: Device families
description: Choose operations from the discovered protocol, model, and capabilities.
---

Account login and discovery use the same cloud HTTP API across families. Open a session with the discovered device; the SDK selects its MQTT adapter. Use typed operations and check the session's capabilities.

| Family | Discovery rule | Use |
| --- | --- | --- |
| V1 vacuum | Protocol `1.0` and vacuum category | Vacuum controls, maps, rooms, and supported camera signaling. |
| B01 Q10 | Protocol `B01`; final model segment contains `ss` | Q10 vacuum operations and LZ4 map data. |
| B01 Q7 | Protocol `B01`; final model segment contains `sc` | Q7 vacuum operations and protobuf map data. |
| A01 Dyad | Protocol `A01`; wet/dry cleaner family | Typed cleaner state and settings. |
| A01 Zeo | Protocol `A01`; washing-machine family | Typed washer state, settings, and cycle start. |

For B01, the `ss` rule is checked before `sc`. Other B01 model shapes and unsupported protocols return `Unsupported` instead of guessing a command format.

Q7 and Q10 in this table identify protocol families. A product named Q7 that reports `1.0` follows the V1 adapter. A product name alone does not establish its protocol or capabilities.

Vacuum commands do not apply to Dyad or Zeo appliances. A01 has no vacuum map operations. Within a vacuum family, device firmware and capability metadata determine which settings and controls are available.
